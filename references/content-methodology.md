# 选题流水线

> learn-with-u-writer 从「作者给了选题」开始接管。这份文件管再上游一步：选题本身过不过关、属于哪类、按哪类写。

## 第一刀：loss function 判据（先于一切）

一个朴素的筛选标准：

- 选题核心若是「教工具、调 API、标准 demo」——可精确定义、有标准答案的工作，正在被 AI 卷成白菜价，慎选。
- 选题核心若是「问题定义、判断取舍、行业直觉、踩坑复盘」——写不成标准答案的部分，是壁垒，优先。

一句话：教工具的死，教判断的活。

## HKR 质检（动笔前过一遍）

- **H（Happy）**：够有趣、有悬念吗？标题和开头能让人点开吗？
- **K（Knowledge）**：有信息量吗？看完能学到新东西吗？
- **R（Resonance）**：能戳中情绪吗？让人「对对对我也是」吗？

S 级选题三项兼备；及格至少两项；只占一项，重审；零项，放弃。

## 文章五原型（写法重心各不同）

| 原型 | 核心姿态 | 写法重心 |
|------|---------|---------|
| 调查实验型 | 我替你去做了这件事 | 过程叙事 + 层层发现 + 真实反应 |
| 产品体验型 | 跟我一起玩 | 场景演示 + 真实感受 + 自然对比 |
| 现象解读型 | 你注意到吗？背后是什么 | 观察 → 好奇 → 研究 → 升维 |
| 工具分享型 | 我发现了一个好东西 | 个人故事铺垫 → 工具展示 → 效果惊艳 |
| 方法论分享型 | 压箱底的掏给你 | 每节落到可执行动作 + 坦承学习曲线和失败点 |

## 选题来源（按你自己的情况建库）

- **你的素材库**：自己的经历、踩过的坑、验证过的判断——建一个「故事银行」，每条标注可用敏感度
- **你的现场**：工作中真实的问题、对话、报价、翻车——一手痛点
- **你的数据**：已发布内容的反馈，验证过的钩子与开头
- **你的读者**：评论区、社群、私聊里的高频问题——需求即选题

## 与写作流程的衔接

选题过 loss function 刀 + HKR → 归入五原型 → 带着原型进入 learn-with-u-writer Step 1（作者给选题 + 情绪 + 素材）。

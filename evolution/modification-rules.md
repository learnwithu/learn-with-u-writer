# 修改规律（示例：原作者的真实提取记录）

> **这是一份产出示例。** 展示「进化提取」机制运行几轮后，`modification-rules.md` 会长成什么样：AI 对比作者初稿和终稿，提取反复出现的改动模式。
> 规则格式：观察（现象）→ 判断（原因）→ 参考（AI 怎么做）。
> **不是铁律，是参考。** 出现 3 次以上才写入高置信度区。

---

## 高置信度（≥3 次，Bob 已确认）

### 1. 砍软留硬

- **观察**：Bob 把 Chelsea 的"能力鸿沟""Clontent 扩展非取代""design encodes values"全删，只留 string change（两周→20 分钟）那条硬案例；同时把 Shrivu 的硬数据论证（个体 100 倍但组织只 10-20%，效率与规模成反比）加进来。4+ 处软概念被砍。
- **判断**：Bob 要的是数据 / 机制 / 反直觉论证，不是情绪 / 价值观 / 感受。软概念除非是文章主线，否则是噪声。
- **参考**：选素材时分两堆——硬逻辑（数据 / 机制 / 反直觉）和软概念（情绪 / 价值观 / 感受）。优先硬的；软概念只在它是文章主线时保留。

### 2. 核心词贯穿

- **观察**：Bob 把"转置组织"弱化成"loop 组织"，"loop owner"简化成"looper"，"slop"换成"垃圾"，"bus factor = 1"换成"looper 离职问题"。4 处术语替换。
- **判断**：一篇文章选定 1 个核心词反复强化，比"忠实保留原文所有术语"更有力。生硬术语哪怕原文用的，也要中文化或替换。
- **参考**：动笔前选 1 个核心词贯穿全文。其他术语要么中文化（slop→垃圾），要么替换成直白表达（bus factor→离职问题）。英文术语只在它已是行业通用词（loop / prompt / agent / context layer）时保留。

### 3. 让步再转折

- **观察**：我开头写"我没接话"（直接否定），Bob 改成"呃…好吧…有一说一，他的公司确实算做得不错的"（让步再转折）。全文多次这种节奏。
- **判断**：直接打脸显得傲慢。先承认对方部分成立再反驳，更圆融也更有说服力。
- **参考**：否定某个观点前，先用"有一说一…""客观讲…""如果对比 X，确实…"承认对方部分成立，再转。

### 4. 段标题直白专业，不装可爱

- **观察**：Bob 把"配 AI"改"用 AI"、"什么是 loop"改"Loop 式组织架构"、"那你自己呢"改"你怎么办"、"泼几盆冷水"改"可预见问题"。5 处标题改写。
- **判断**：段标题用直白专业词，不要口语化装可爱（"那你自己呢""泼冷水"），也不要生硬直译。
- **参考**：段标题用读者一眼能懂的专业词。"可预见问题"优于"泼冷水"，"你怎么办"优于"那你自己呢"。

### 5. 语气词密度

- **观察**：我初稿几乎没有语气词，Bob 大量使用"呃…好吧…/……/哦~/吧/呢"，加日剧梗（"太太，你也不想你的先生被辞退吧"）、文化引用（"高山流水伯牙子期"）。
- **判断**：语气词和梗是 Bob 的口语指纹，密度太低读起来像 AI 通用文。
- **参考**：初稿主动加 Bob 的口语指纹——语气词（呃 / 吧 / 呢 / 哦~ / ……）、网络梗、文化引用、自嘲。宁可多加让 Bob 删，不要欠账。

## 低置信度（1-2 次，待验证）

### 6. 荒诞具体细节

- **观察**：我把工具栈写成"ChatGPT/Claude/Coze"（泛），Bob 改成"minimax/mimo/Coze/n8n/飞书多维表格"+"token 消耗量 1 亿"（荒诞具体）。
- **判断**：具体到工具名 / 天文数字的例子，比泛泛罗列有画面感、有钩子力。
- **参考**：举例时具体到工具名（minimax / n8n 而不是"各种 AI 工具"）和荒诞细节（token 1 亿），让读者有画面。

### 7. 分情况给建议

- **观察**：Bob 在第四段把"你自己怎么办"分成"如果你是专才…"和"如果你是通才…"两个分支。
- **判断**：读者群体不单一时，分情况给建议比"一刀切"实用。
- **参考**：当建议面向不同角色（专才 / 通才、老板 / 员工、A 类客户 / B 类客户）时，用"如果你是 X…如果你是 Y…"结构分情况。

## 使用说明

1. **读取时机**：CC 在生成初稿前读此文件，把规律作为**参考偏好**而非**强制约束**带入写作。
2. **写入流程**：
   - CC 对比初稿和终稿，提取候选规律
   - 呈现给 Bob，说明观察依据（改了哪几处）
   - Bob 确认后写入对应置信度区
   - 追加到本文件的 `updated` 字段
3. **淘汰机制**：
   - 如果某条规律导致 AI 输出千篇一律，Bob 可标记淘汰
   - 已内化到 SKILL.md 的规则，迁移到"已淘汰"区并注明原因
4. **规模控制**：高置信度区不超过 15 条，满了就淘汰老的或合并同类项。
